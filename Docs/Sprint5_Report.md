**How it's built:** Unreal's Python API can't edit Niagara emitters, so I wrote an editor-only C++ module that builds the systems from code. It clones Unreal's lightweight emitter template, adds one emitter per layer (core, sparks, smoke...) and sets each module's values. Each effect is defined in one place in code and can be regenerated by the pipeline. The game spawns every effect through one helper class.

## Lighting Pass 3

<!-- Before/after contact sheets: Saved/LightingPass3/alpha_before.jpg, alpha_after.jpg, outpost_after.jpg -->
*[Before/after: six fixed cameras along Operation Redline (camp, trench, bridge, bunker, sniper perch, gate)]*

**The bug behind the blue look.** Since the Outpost, every map had come out blue-washed, and earlier lighting passes tried to fight it with brighter, warmer lights. The real cause was in the level-building scripts. Unreal's Python `unreal.Color(r, g, b, a)` actually takes its arguments in memory order (**B, G, R, A**), so every light colour had red and blue swapped:
- warm trench lamps came out sky blue,
- the "warm" sun and sky light were bluish,
- the red enemy-territory lights were blue,
- the Blue camp's lamps were orange.

I fixed it by naming the channels (`unreal.Color(r=..., g=..., b=...)`) in a shared `rgb_color()` helper in all three level scripts.

**The relight.** With the colours finally correct, the old intensities (cranked up to fight the blue cast) blew everything out, so I relit each section:

| Area | Change |
|---|---|
| Whole valley | Warm late-afternoon sun; sky light raised from 0.3 to 0.9 to lift the shadows; saturation 0.95; bloom halved so coloured lights don't smear |
| Blue camp | Blue lamps cut to a soft accent (4800 → 600), so the shaded camp reads cool against the warm valley |
| Supply trench | Lamps dimmed (1400 → 300) and given a shorter reach: warm pools instead of blown-out walls |
| Forward post / bridge | Dimmed by about 60% |
| Bunker, patrol yard, gate, command yard | Red-territory lights desaturated to red-orange and dimmed by 50-70%, so enemy ground still reads red without drowning the robots |
| Outpost demo map | Same colour fix, plus thinner, greyer smog and lower exposure: warm sun, warm smog and brown materials had stacked into solid orange |

The lighting is built by the level scripts, so these values live in `ue_setup_alpha.py` / `ue_setup_gameplay.py` and survive every rebuild. The title screen and space battle maps were rebuilt with the fix too.

## Playtest Report: Test Candidate 02

**Tester:** a friend, outside class. Not a core-demographic player ("not exactly my core demographic but always love branching out").
**Build:** TC02, packaged Windows build.
**Format:** played Operation Redline unsupervised, then sent written feedback.

### What worked

| Area | Feedback |
|---|---|
| Hacking | "I do think the hacking has improved lots." The puzzle "will take some getting used to," but it's "more understandable" playing it than watching footage. |
| Level | Improved "as a whole"; "the touch up on the gates look nice." |
| Console disguise | Crouching into a console as a disguise was "a neat touch." |
| Controls | Liked the **C** toggle for crouch over holding a key: "as someone who hates holding keyboard buttons." |
| Overall | "Overall very nice work, will totally buy this when it drops." Offered to play it on YouTube when it's finished. |

### Issues found

| # | Observation | Severity | Action |
|---|---|---|---|
| 1 | Enemies in the **first fight** didn't seem to respawn after dying, while others did. | Medium (consistency) | Only robots assigned to a robot dispenser are rebuilt; the first fight has no dispenser. Next: make it clear which robots respawn (visible dispenser or explanation in dialogue), or add a dispenser. |
| 2 | **Snipers lock on** (laser sight) before the player has the sniper rifle, but don't shoot until the player gets it. | Low (no gameplay problem reported) | Check the Marksman's aggro trigger. The early laser may read as a threat that never comes; delay the lock-on, or keep it as foreshadowing. |
| 3 | The hacking puzzle has a learning curve. | Low | Matches earlier tests: the puzzle went from too easy → too hard → simplified. Next: a one-time tutorial prompt the first time you hack. |

### How earlier feedback shaped this sprint
- Sprint 4 testers said hacking was **too easy**, so I added the hack puzzle.
- The first version of the puzzle was **too hard**, so I fixed the node layout and added click-to-connect wiring.
- This playtest confirms the change: hacking "improved lots" and is understandable in play.

## Problems solved during the sprint

- **Niagara can't be scripted from Python.** I wrote an editor C++ module that builds the effects instead. It needed Niagara's internal headers added to the build.
- **Additive fireballs vanished against bright floors.** I gave them their own translucent fire material.
- **AI navigation across drops:** Unreal's generated jump links only appear at exact depths, so I set up a "ladder" of jump configs (2 m to 12.5 m in 1.5 m steps). Enemies also have to be stopped from riding a lift back up when the player is right next to them.
- **Checkpoint restore:** placed actors are matched by path, and the restore runs in two passes around level start, so robots, pickups and objectives come back correctly.
- **Enemy squads fought each other before the player arrived.** Squads now start beyond each other's sight range.
- **Every map looked blue-washed.** Unreal's Python `unreal.Color` swaps red and blue when given positional arguments; I found it by dumping the lights' actual colours from the map, instead of tuning lights by eye.
